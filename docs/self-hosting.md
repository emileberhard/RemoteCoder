# Build your own client

Basic chat needs your own Mac gateway and provider login. It does not need a
push broker, llm-router, Maps key, CloudKit library, managed-device service or
maintainer configuration. Follow the [gateway guide](../host-daemon-rs/README.md)
first. A matched Codex runtime is required even when you choose Claude Code
for a conversation.

## Native build

Install Xcode matching [`.xcode-version`](../.xcode-version), `just`, `uv`, Bun and the Rust toolchain. Select that Xcode in your
local environment, or set `RC_XCODE_DEVELOPER_DIR` for a build invocation.
The public build runner uses this Mac by default and supplies its own bounded
cache policy when there is no maintainer policy.

```sh
just setup
just ios-build
just mac-build
```

These compile without signing or installing and do not boot a simulator.
Open the committed `RemoteCoder.xcodeproj` for your own run target.
For signed device installs, use your own Apple Developer team, app identifiers,
provisioning profiles and enabled capabilities for the app and extensions.
The [root verification policy](../AGENTS.md#build-install-and-verify) describes
focused tests and explicit device selection.

Tracked [`Config/RemoteCoder.xcconfig`](../Config/RemoteCoder.xcconfig) contains
example defaults and optionally includes ignored `Config/Local.xcconfig`.
Use that local file for your signing team and namespace:

```xcconfig
DEVELOPMENT_TEAM = YOUR_TEAM_ID
RC_BUNDLE_ID = com.yourcompany.YourClient
RC_APP_GROUP = group.$(RC_BUNDLE_ID)
RC_ICLOUD_CONTAINER = iCloud.$(RC_BUNDLE_ID)
```

Use your own name and icon for a distributed fork. Extension identifiers and
App Group access derive from these settings. The app uses its default Keychain
access group; the signed bundle ID and team determine that identity. Do not use
another operator's profiles or copy their private local file.

No runtime host seed is required to compile. Add a host in Settings with the
address and operator token generated by gateway setup. Choose a folder reported
by that host; local paths are not portable between machines. The optional
ignored `RemoteCoder/Resources/RemoteCoderLocalConfig.json` can seed your own
installation; its [example](../RemoteCoder/Resources/RemoteCoderLocalConfig.example.json)
shows the shape. Keep tokens and API keys out of distributable builds.

## Optional features

- Maps/navigation stays unavailable without your own restricted Google key,
  enabled Maps/Navigation APIs and user permission. Configure the key through
  ignored runtime configuration. The restriction must match your bundle ID.
- Speech controls depend on the gateway's reported `speechAvailable` capability.
  A configured speech relay owns provider credentials; the app carries none.
- Automation controls select only a host reporting authoritative automation
  capability. Missing or unread capabilities remain unavailable.
- Push/VoIP/location and Live Activities need a broker authorized for your bundle
  IDs and Apple signing capabilities. Native chat does not need that broker.
- Shared dictation requires your own CloudKit container and explicit opt-in.
- Custom notification sounds require explicit HTTPS origins in
  `RC_NOTIFICATION_SOUND_ORIGINS`; use only origins you control.

[PRIVACY.md](../PRIVACY.md) describes what each optional feature sends and stores.
Maintainer fleet deployment and physical-device delivery are separate from this
public build path and live in the private
[operations entrypoint](https://github.com/emileberhard/RemoteCoder-deploy/blob/main/AGENTS.md).

## Browser

Follow [web-client/README.md](../web-client/README.md). The Bun bridge holds
private gateway credentials; the browser receives a session cookie. Configure
HTTPS, a private access key for remote origins and your chosen network admission.
Every admitted session can act on all gateways bound to that bridge.
